# 客户 Excel 拆分工具

将多个 Excel 导入可持续追加的 DuckDB 数据库，按日期、分区和客户拆分导出。Windows x64 版解压整个 ZIP 后双击“Excel客户拆分.exe”。运行文件、同目录的 `_internal` 和 JSON 配置需要放在一起。

## 从导入到导出

1. 点击“新建库”选择本地磁盘及文件名，或点击“打开库”接着使用已有的 `.duckdb`。首次启动会在当前用户的本地应用数据目录建立默认库。程序会记住库的位置。重启时如果库里已有数据，Excel 导入区会自动收起，可以直接选择客户和导出条件。
2. 需要导入时，展开顶部的 Excel 导入区，点击“选择 Excel…”，一次选齐同一批次的所有文件，再点“开始导入”。默认读取每份文件的第一个工作表，在前 30 行查找表头。公式使用文件中已保存的计算结果，遇到缺少数值缓存的公式会提示位置，整批回滚。
3. 在左侧客户名单中选择本次要导出的客户，在右侧选择客户字段、可选分区字段，并勾选要导出的字段。名单和字段均可搜索；搜索时，全选和清空作用于当前显示的项目，隐藏项目保留原有选择。重名表头可分别选择，导出的列名沿用原表。分区规则来自 `regions.json`，预设客户来自 `customer_config.json`。名单为空时导出全部客户。
4. 年、月、日由同名列自动识别。点击“日期范围”下的日期按钮打开日历，依次选择起止日期，会把同一客户在该范围的明细写入同一组文件。清除日期筛选时按天分目录。无有效日期的行在全量导出时归入当天的文件夹。
5. 选择输出目录，点击“开始拆分导出”。输出路径为 `日期或日期范围/分区/客户.xlsx`。单表最多写入 1,048,575 条明细，超出后自动分卷。完成后在输出目录生成本次 CSV 清单，列出每个工作簿及其明细行数。复用目录会保留以前导出的其他客户和旧分卷，交付本次结果时以本次清单为准。取消导出可能留下已完成的工作簿，完整清单只在整次成功后生成。

## 重叠日期怎样处理

先导入 1–12 日，再导入 11–20 日，1–10 日保留，11–12 日使用新批次的全部明细，13–20 日追加。同一天分在多个文件里时，需要在一次导入中选齐。新快照里已经撤销的明细随旧快照一起移除。内容完全相同的两笔业务也会各保留一行。只替换新批实际出现的日期，中间某天没有任何输入行时，库中该日的数据会保留。

导入按整批提交，读取失败、行数核对失败或提交前停止都会回滚。日志分别显示输入行数、覆盖日期、旧行数及无日期行数。无有效日期的行无法参与按日替换，重新导入字节内容相同的 Excel 会替换该文件的无日期行。重新保存过的文件可能有新的指纹，其无日期行会另外保留。

## 旧 SQLite 与二次分析

新建一个空库，在“配置维护”中点击“迁移旧 SQLite”选择旧的 `splitter.sqlite3`。程序以只读方式打开旧库，按先后迁移成功批次，逐源核对总行数及金额类字段的分月数值合计，再按整日快照规则发布。相同旧批次可安全重试。旧版本入库前已经丢失的字段值需要从原 Excel 补录。

关闭应用后，可以用 DuckDB 客户端打开同一个文件。视图 `analysis_details` 使用界面中的字段名，底表 `details` 保存业务日期、来源编号和原行号，`sources` 保存源文件信息。业务列使用 UNION 保留单元格原有的文本、整数、小数和布尔类型，文本编码的前导零可保留。以下示例对名为“金额”的列汇总数值单元格，精度取小数点后 12 位。

```sql
SELECT SUM(COALESCE(
    union_extract("金额", 'm'),
    CAST(union_extract("金额", 'i') AS DECIMAL(38, 12)),
    CAST(union_extract("金额", 'n') AS DECIMAL(38, 12))
)) AS "金额合计"
FROM analysis_details;

SELECT day, row_count FROM calendar ORDER BY day;
```

数据库使用列式压缩。每批按业务日期排序写入，日期范围查询可利用 DuckDB 自带的分块最小值和最大值统计，日历直接读取日期汇总表。客户字段可任意选择，按当前查询在数据库内筛选并读取所选列。“整理日志”执行检查点。批次替换后，文件会复用可用空间，实际文件大小受字段数、文本重复率及数据顺序影响。

## 运行测试和构建

需要完整的 Python 3.11 或更高版本及 Tk。运行下面的命令可执行完整性测试和桌面流程自检。

```sh
python -m pip install -r requirements.txt
python -m unittest -v
python app.py --self-test
```

以下命令分别生成真实 Excel 文件做全链路测试，以及在生产表结构中直接生成大规模明细做查询测试。均使用临时数据库，不接触业务库。可用 `--directory` 指定有足够剩余空间的本地目录。

```sh
python benchmark.py --xlsx-rows 100000
python benchmark.py --rows 10000000 100000000
```

真实 Excel 测试覆盖造文件、导入、导出及逐格核对。数据库测试用 360 天、1,000 个客户和 6 个业务字段，按批发布，核对全库行数和单号校验和，再导出某月某客户并逐行核对。规则生成的数据具有较高可压缩性。

使用 Windows x64 Python 运行 `build_windows.ps1`，脚本会执行单元测试、构建程序并自检最终 EXE。GitHub Actions 的 **Build Windows x64** 工作流可生成完整 ZIP 包。
